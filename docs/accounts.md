# Accounts — حساب‌های کاربری

این اپلیکیشن برای کافه‌های تک‌نفره و مجموعه‌های چندکاربره/چندشعبه‌ای طراحی شده است.

## تصمیم‌های معماری

- مدل احراز هویت همان `django.contrib.auth.models.User` پیش‌فرض Django است.
- ساخت User سفارشی در این مرحله انجام نمی‌شود.
- اطلاعات تکمیلی در `UserProfile` نگهداری می‌شود.
- هر مجموعه در `AccountConfiguration` حالت فعالیت خود را انتخاب می‌کند.
- نقش‌ها به مجموعه کافه تعلق دارند و عضویت کاربر در هر شعبه جداگانه ثبت می‌شود.
- تغییر حالت تک‌کاربره به چندکاربره، ساختار دیتابیس را تغییر نمی‌دهد.

## مدل‌ها

### AccountConfiguration
تنظیمات راه‌اندازی حساب‌های یک مجموعه:
- `SINGLE`: حالت تک‌کاربره؛ مالک دسترسی کامل دارد و ایجاد نقش و عضویت کارکنان لازم نیست.
- `MULTI`: حالت چندکاربره؛ دسترسی کارکنان از طریق عضویت شعبه و نقش تعیین می‌شود.
- `owner`: حساب مالک مجموعه.
- `setup_completed`: وضعیت تکمیل راه‌اندازی اولیه.

### UserProfile
اطلاعات تکمیلی کاربر شامل نام نمایشی و شماره تماس.

### Role
نقش قابل تنظیم برای هر مجموعه، همراه با مجوزهای استاندارد Django.

### BranchMembership
اتصال یک کاربر به یک شعبه و نقش او در آن شعبه. هر کاربر در هر شعبه فقط یک عضویت فعال/غیرفعال دارد؛ می‌تواند در شعبه‌های مختلف نقش‌های متفاوت داشته باشد.

## قواعد دسترسی

تابع `user_has_branch_permission(user, branch, permission_codename, app_label=None)` در `services.py` بررسی دسترسی را انجام می‌دهد:
1. کاربر ناشناس: رد.
2. superuser: مجاز.
3. مالک ثبت‌شده مجموعه: مجاز.
4. حالت تک‌کاربره: سایر کاربران مجاز نیستند.
5. حالت چندکاربره: مجوز باید در نقش عضویت همان شعبه وجود داشته باشد.

این تابع باید در لایه سرویس/API نیز استفاده شود؛ صرفاً مخفی کردن گزینه‌ها در رابط کاربری امنیت ایجاد نمی‌کند.

## راه‌اندازی و تست محلی

پس از دریافت تغییرات:

```powershell
python manage.py check
python manage.py makemigrations accounts
python manage.py migrate
python manage.py test apps.accounts
python manage.py createsuperuser
python manage.py runserver
```

سپس در پنل مدیریت:
1. یک `CafeProfile` و حداقل یک `Branch` ایجاد کنید.
2. در `AccountConfiguration` برای مجموعه، مالک را انتخاب کنید و حالت را تعیین کنید.
3. برای حالت چندکاربره، نقش بسازید و مجوزهای آن را انتخاب کنید.
4. کاربر را در `BranchMembership` به شعبه و نقش موردنظر متصل کنید.

## نکات مرحله فعلی

- رابط راه‌اندازی اولیه و API مدیریت کارکنان هنوز در مراحل بعدی ساخته می‌شوند.
- ایجاد دعوت‌نامه، بازیابی/تغییر رمز، محدودیت نشست‌ها و گردش تأیید دسترسی در این نسخه پیاده‌سازی نشده‌اند.
- حذف شعبه دارای عضویت به دلیل `PROTECT` مسدود است؛ ابتدا باید عضویت‌ها تعیین تکلیف شوند.
- مالک مجموعه باید یک کاربر معتبر و فعال باشد.
